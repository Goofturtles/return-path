What this actually checks

    

      

        
Authentication

        

          SPF asks whether the sending server was on the domain owner's approved list.
          DKIM checks a cryptographic signature over the message. DMARC is the part
          people skip: it ties those two results back to the address you actually see,
          and publishes what the domain owner wants done when they don't match.
        

        
Alignment

        

          A message can pass SPF and still be a forgery, because SPF validates the
          envelope sender — not the From line. Return Path shows both addresses side by
          side so you can see whether the pass applies to the name on the letter or only
          to the postmark.
        

        
Impersonation

        

          Display names are free text and are never verified. Putting a real address
          inside the name field is enough to fool every mobile mail client, because they
          show the name and hide the address.
        

      

      

        
Lookalike domains

        

          Punycode is decoded, so a domain registered as xn--pypal-4ve.com
          is shown as the pаypal.com you would have seen on screen —
          with a Cyrillic а. Confusable characters are folded before comparison, which
          catches the digit-for-letter and rn-for-m swaps too.
        

        
Links

        

          Anchor text is compared against the real destination. URLs that hide behind an
          @, point at bare IP addresses, or route through shorteners are
          pulled out and shown for what they are.
        

        
Attachments

        

          Filenames are checked for double extensions — the trick that works because
          Windows hides the real one by default — and for formats that can carry macros.
        

      

    

  


  

    
What this can't do

    

      A tool that only tells you what it caught is half a tool. Here is where this one
      stops:
    

    
    
      
  • 
        It cannot re-verify a signature. DKIM verification needs a DNS lookup for
        the sender's public key, and this page makes no network requests by design.
        It reads the result your mail provider already recorded. If a message was
        forwarded, that record may be missing or stale.
      
    • 
      
  • 
        It cannot see a compromised account. When an attacker is sending from a
        real mailbox they have stolen, every check passes because everything is genuine
        except the person typing. That is what the business-email-compromise specimen
        demonstrates, and why the verdict never says "safe".
      
    • 
      
  • 
        Headers can be stripped. Some clients and gateways remove or rewrite
        headers before you see them. Less evidence means a less confident answer, not a
        safer message.
      
    • 
      
  • 
        The brand list is finite. Lookalike detection compares against a fixed
        list of commonly impersonated domains. A lookalike of a domain that isn't on that
        list won't be named, though the link and alignment checks still apply.
      
    • 
      
  • 
        "Authenticated" is a statement about a domain, not a person. It means the
        message really came from where it claims. It does not mean the request inside it
        is reasonable.

      Return Path — built for the TLN Cybersecurity Challenge, September 2026.
      Everything runs in this tab: the page loads three JavaScript files and then makes
      no further network requests. You can disconnect from the internet and it will
      continue to work, which is the only honest way to handle somebody's private mail.
    

    

      The specimens are synthetic — written for this tool, containing no real message,
      address or recipient. Brand names appear only as the targets of impersonation,
      which is what the tool exists to detect.
